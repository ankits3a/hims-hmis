## 0b. The second reading — where this revision departs from the first draft

A second session re-measured the first draft against `78f5947` the same afternoon. Every decision
below stands except three, changed on evidence, and one set of numbers corrected.

1. **The catch-up deploy moves from week 3 to week 1–2, and stops waiting for UAT.** The first
   draft treated 21 migrations as "one large, risky step" and put a UAT rehearsal in front of it.
   That framing borrows from a live system. Production has never left `commissioning`, no department
   has opened on it, and its owner tests on lane-built demo stacks rather than on it — so the only
   data at risk is his own trial rows. `deploy.sh` has already been run against this box four times
   (34 → 38 → 43 → 46 → 56 migrations), and the one step in the batch whose behaviour the deploy
   itself changes — 18c's licence gate — already has a rehearsal bench: the AERB demo on `:8444`
   (`/opt/hmis-aerb-demo/file-demo.sh`, four `DEMO` certificates) was built for exactly that walk.
   Waiting does not make the batch safer; it makes it larger, and a deploy into an empty hospital is
   the cheapest deploy this project will ever do. So the order is: `seed:lab`, the watermark guard,
   the census and the pool values land (11i T1, T4, T2 + 11j steps 1–2), T7's runbook is written,
   and **the owner deploys production at the end of week 1 or the Monday of week 2**. UAT follows
   and hosts the pilots, which is what it is for (G5), rather than gating a deploy. **One fact only
   the owner holds** reverses this: if any real patient has been registered on production, the first
   draft's order (UAT first, deploy in week 3) stands. He can say so in one line; nothing else in the
   document moves.
2. **11i is executed by the pharmacy lane, which becomes S; the LIMS lane takes 17-E T7 at once.**
   Both worktrees sit parked on documentation branches today (`tools/lane.sh status`), so both are
   idle and the first draft's "L is idle, P is on the train" no longer discriminates. The lane that
   builds UAT should be the lane that runs it — continuity is the whole point of a commissioning
   lane — and T7 touches `enterResult`, the CRITICAL path the LIMS lane has owned since 17b.
3. **The restore drill joins G1.** `deploy.sh` step 7 installs a weekly `restore-drill.sh` host cron
   (11c D11) and its watcher rule. Neither the report nor the first draft read its log. A department
   does not pass G1 until the most recent drill log has been read and its date recorded — no new

4. **Numbers.** Box memory is 7 GB used, 7 GB available of 15 (the first draft's 9.3 GB + 5 GB of

## 1. The four questions, settled

### Q1 — What opens first, and what does "open" mean?

**The laboratory, through the front desk — on a UAT environment first, then on production.**
DECIDED. The lab is the only department whose code, runbook and demo seed all exist; its five seats
and report centre were built to a signed design; and its runbook §11 already contains the
walk-through a human performs. Pharmacy is second (runbook exists, code never deployed, item master
is the chief pharmacist's data). Radiology is third (deployed, but 18c's real certificates are the
owner's data and the machines stop without them).

**"Open" is a seven-gate checklist, not a merge and not a mode** — §3. The gate a department
cannot pass by itself is G7, the hospital-wide exit from `commissioning`, and that is O6.

### Q2 — Does the constraint still sit on building?

**No.** DECIDED, with the measurements in §0 rows 3, 5 and 6. Ninety-three PRs have merged since
2 September, the day production was last deployed. The owner absorbs features through lane-built
demo stacks, one human, by hand. Every one of the IPD gate's blocking conditions is a human act.

**So the roadmap re-shapes around it in three ways.** (1) A commissioning track — Track S — runs
beside the build tracks with its own artefacts (§3). (2) **One of the four lanes becomes the
commissioning lane** for the quarter: it owns UAT, runs the runbooks, drives the seat drills, and
fixes what the pilots find. The build lanes drop from four to three. (3) A phase is not closed until
its stand-up path has been *executed on UAT* — the S-gate joins EXECUTE-METHOD §5A (§8).

**The build does not stop.** Plan 20 (roster) is on the IPD gate's critical path and is the one
substrate the quarter must land (Q4). Everything else the lanes build this quarter comes out of the
pilots, not out of the department series.

### Q3 — The deployment strategy from here

**One catch-up deploy first, in weeks 1–2, in a declared window — then continuous to UAT, weekly
to production, module-at-a-time OPENING behind the census.** DECIDED (order revised in §0b.1).

- **UAT** (`hmis-uat`) is the same `deploy.sh`, same images, same seeds, on this box, **replacing the
  two ad-hoc demo stacks** (net memory neutral: the box is at 9.3 GB used with 5 GB of swap in use
  and cannot carry a third stack beside them). It carries synthetic data behind an environment door
  production never sets (11i D5). It moves to a second server if the owner buys one — §6 item 1.
- **Every green merge-train batch deploys to UAT**, run by the orchestrator through the test mutex
  (a docker build is a builder, like jest). **Production deploys weekly, by the owner's hand**, from
  a clean tree, as `deploy.sh` already requires. Migrations stay additive (CLAUDE.md), the journal
  stays monotonic (11i T4 makes the migrator refuse otherwise).
- **Not** "batch until ready": the batch is already 20 migrations and two modules, and the one thing
  that makes it risky — 18c's licence gate — does not get safer by waiting. **Not** "flag every
  module": a flag per module is a second configuration surface nobody runs the census on. A module
  is *deployed* when its migration lands and *open* when it passes §3; between the two it is dark
  because nobody holds its roles and nothing has activated its Class A/B definitions.
- **Order within a batch is not a thing to decide.** Production runs one `main` tip; the migrator
  applies every pending entry in journal order; a defect that must not reach production is a
  precondition on *which tip* is cut. The artefact is a `deploy-blocker` label on the fixing PR
  (§0 row 10): no deploy takes a tip while one is open. For the catch-up deploy, which does not
  pass through UAT (§0b.1), the label being clear plus #108/#110 merged plus `standup:check all`
  is the proof; from the second weekly deploy on, the S-gate on UAT proves the tip as well. The
  one coupling found so far becomes exactly that: the catch-up tip includes #108.
- **The catch-up deploy** (11i T7) is one ordered runbook: the last restore-drill log read; 18c's
  §0 rehearsal performed on the AERB demo bench that already exists (migrate without a licence,
  watch the CT refuse, file four `DEMO` licences, watch the gaps empty); then production in a
  declared radiology window of under an hour, licences filed from the certificates immediately after
  the migration lands, `standup:check` read before and after. It does **not** wait for UAT (§0b.1).
  PR #73 closes as superseded the moment `main` is deployed — its content is already there.

### Q5 — The analyser rerun rule (17-E T7)

DECIDED: **a machine never supersedes; a human always does.** A row with `entry_mode='interface'`
for an analyte that already carries a value on the same specimen is written with `rerun_of` set and
`supersedes_result_id` NULL — both live, neither reported until the bench chooses one **with a
reason**, recorded on the row and as an audit event. A row with `entry_mode='manual'` keeps M3's
rule unchanged: a re-key supersedes, and the chain is the auditor's path. `interface_down` is
written only by the bridge's own heartbeat lapse, never by idleness. This widens neither rule; it
separates them on a column the row already has. Executed as 17-E T7 by the LIMS lane, migration for
the choice, the reason and the audit row, numbered at rebase.

### Q6 — The connection pool (nesting remediation steps 1–2)

DECIDED: `connectionTimeoutMillis: 10_000` and `max: 20` for the API, `max: 10` for the worker,
both read from env with those defaults (nothing under `docker/prod` overrides `max_connections`, so
pg's default of 100 applies; the exporter, pgBackRest and two app processes fit with headroom). Step 1 converts an
invisible hang into a logged error; step 2 makes five concurrent invoice issuances unremarkable and
turns step 3 from urgent into scheduled. Step 3 is **11j** (§7), a one-week phase in the quiet
window that exists now, owned by the lane that closed 17d (it wrote the audit-on-its-own-transaction
rule the fix must not collapse).

## 3. The commissioning track — what "open" means, as a repeatable checklist

Seven gates. G1–G4 are answered by a script (11i T2, `standup:check <module>`), which prints every
red row with the screen or command that turns it green, runs in `deploy.sh` as a non-fatal report
(the `seed-roles` precedent: a verdict about staffing must not abort a migration) and as the hard
gate on UAT. G5–G7 are human acts with an artefact each.

| gate | question | who answers | artefact |
|---|---|---|---|
| **G1 deployed** | the module's migrations are applied, its module is wired at the running base, and the most recent weekly restore drill (`restore-drill.sh`, 11c D11) succeeded | `git ls-tree <base>`; the owner's applied-count query; the drill log | the deploy transcript + the drill log's date |
| **G2 established** | every row the module *throws without* exists: Class C definitions active, approval types registered, config rows, stores | `deploy.sh` seeds + `check-config-present` | the deploy's own gate |
| **G3 loaded** | the department's master data: catalogue and prices, item master and batches, devices and licences, departments and doctors of record | the department head, through the module's screens — **never a seed** on production | `standup:check` green for the module |
| **G4 staffed** | every role key the module declares is held by a named human at hospital scope; the second administrator exists; the bridge accounts exist where a machine will talk | `/admin/users`; `seed-roles`' READY verdict | the `seed:staff` transcript, kept |
| **G5 rehearsed on UAT** | the runbook's seat walk-through and drills, done by a real person at each seat, on synthetic data, in a browser | the department head + the commissioning lane | a dated `## Executed` section appended to the runbook |
| **G6 piloted** | the shadow window on production with paper authoritative; the harvest rows read daily; closes on the runbook's own criterion | the department head; the digest | the harvest, seven days empty |
| **G7 the hospital exit** | `commissioning → ramp`: `validate:config` ok within 24 h — CA signature, active tariff | the owner, once, hospital-wide | the `ops.config_validated` event and the mode row |

**Four rules the track binds, DECIDED, none of them money:**

1. **Production never receives synthetic people or invented clinical values.** `seed:lab-demo`'s own
   reasoning: a synthetic patient is referenced by orders, invoices and results and cannot be
   deleted. UAT carries them behind an environment door; production's env never opens it.
2. **Class C definitions are established by the deploy; Class A and B never are.** Pharmacy's seed
   already activates `pharmacy_dispense`; the lab's two are Class C by their own header and join
   (11i T1). The OT's Class-B seeds stay drafts (DD6 — "the theatre the owner named").
3. **A runbook is not a deliverable until it has been executed once**, and the execution is dated in
   the runbook. Four runbooks exist; zero have run.
4. **Deploy-dark**: a guard that needs configuration ships inert until the configuration exists, *or*
   its configuration surface ships one deploy earlier. 18c is the measured exception (an
   offence-preventing guard, kept as designed) and is handled by a declared window. Every phase doc
   from here states which of the two it chose.
