## 1. What was actually wrong

The owner's report was that a multi-role counter clerk could not move quickly and that walk-in
checkout was tedious. Measured at `69dde01`, the simplest possible walk-in — returning patient,
self-pay, cash — cost **three route changes, three searches for the same person, one hand-typed
encounter id and seven backend calls in seven transactions**.

The cause was structural rather than cosmetic: every screen was a faithful one-to-one projection of
a backend module, and the counter's unit of work is not a module. It is one human from hello to
goodbye. There was no shared patient context anywhere in the web app.

Three rails were found **built and never connected**: `/billing?encounterId=` (documented in the
router, read by the billing screen, covered by its own suite, constructed nowhere),
`switchWithPin`/`switchWithBadge` (built for shared terminals, no UI), and `secondFactor` on the
permission guard (built, zero routes, deliberately).

## 2. The security work (07a), which came first

Auditing for the dashboard found a live confidentiality hole and it was fixed before any UX work.
`GET /opd/patients/:id/timeline` returned **diagnosis and ICD-10 for every past visit** behind
`opd.visits.read` alone — a permission `front_office` holds. So the confidential flag hid a sealed
patient's NAME while leaving their DIAGNOSES readable to a registration clerk.

**The first fix claimed a class and closed three of its four members.** `GET /opd/visits/:id` was
the fourth and the widest — encounter, diagnosis, ICD-10, vitals AND prescriptions in one payload.
It was missed because the sweep looked for reads taking a raw id **and no actor**; that route had an
actor in scope for name-aliasing and simply never passed it to the read. **Presence of an actor is
not evidence of a gate** — recorded in `9e1f196` so the next audit is better.

Also delivered: the PHI access log (`0038`), because reads were essentially unaudited — the only
access ever recorded was a click-through from the command palette; and break-glass, which shipped
complete and **inert**, since `breakGlassBypass` bypasses `@RequirePermission` at the guard while
the sealed refusal is `hasPermission` called inside `getPatient`. The two could never meet.

## 4. The money defect, corrected and closed

The brief and the phase document both said the counter computes no change and silently banks
overpayments. **The first half was false.** `issueInvoice` has always computed `unallocatedPaise`,
the counter has always rendered it, and the locale string reads *"Change due / banked as advance"*.

The real defect: **two outcomes, one record.** The cashier picked and the ledger wrote the same row
either way — an unallocated receipt balance, which *is* a patient advance. Nothing recorded cash
handed back. So when the money was handed over the advance was fictional: the patient's balance was
overstated by that amount AND the drawer was short by it at close, with no row explaining the
variance the cashier then answered for.

Closed end to end: the cashier declares, `receipts.change_given_paise` records, `expectedCash`
subtracts. The mutant quantifies it — with the subtraction removed the drawer expects ₹700 where
₹680 is owed.

## 5. What is NOT done, stated plainly

- **07a T3 assertion A3** — the reader is told, before the read completes, that an out-of-context or
  sealed access is recorded. It is a web change and belongs with 07c's desk work, not a server stub
  that would make the control look present.
- **The walk-in's atomicity gap** (§3 row 2). A visit can still be open and unbilled. That is
  exactly today's behaviour and no worse; the fee gate already refuses the consultation.
- **Care-relationship gating on reads is LOGGED, not enforced** (07a DD3). Any holder of
  `patients.read` can still open any patient. Blocking clinical reads is how people get hurt; the
  answer chosen was attribution. The owner should know this was a decision, not an oversight.
- **`opd_queue_entries` still has no actor columns** — who *called* a token is recoverable only from
  events. 07c T6 closes the session half; the entry half remains.
- **T7 needed no code**, and that is recorded rather than closed by fiat: `opd-vitals.tsx:140`
  queries `GET /opd/visits?status=registered`, which is precisely the state the counter leaves a
  walk-in in, so the patient appears on the vitals worklist automatically.

## 6. Findings for whoever comes next

- **`@RequirePermission` is `SetMetadata` on ONE key.** Stacking two decorators silently drops one.
  The walk-in route was written that way first and would have let a holder of `opd.visits.open`
  alone register patients. A second permission must be asserted in the service.
- **A pre-existing timing flake**: `command-palette.test.tsx` > "A WEDGE SCAN OPENS THE PATIENT"
  failed once inside a full verify and passed 12/12 in isolation. The palette distinguishes a
  scanner from a human by keystroke timing (`WEDGE_MAX_MS = 120`), so a loaded run drifts past the
  window. It wants an injected clock; it will flake in CI until it gets one.
- **`.print-doc` is `position: fixed` at the origin**, so two printable nodes overprint rather than
  making two pages. Combining documents means one node with sections.
- **A mutant that dies for the wrong reason is not evidence.** T6's R2 first died because the
  duplicate check caught the replay, not because idempotency was missing. Isolate the behaviour.
- **`nav-parity.test.ts` parses `router.tsx` by regex, and required `permission` to be the LAST
  field of each entry.** Adding a third field (`group`) made every entry stop matching — and the
  test THREW *"parsed to zero entries — this parser is stale"* rather than reporting no drift over a
  list it had failed to read. That is the guard working exactly as §2.49 built it to: the silent
  false green is the failure mode it exists to prevent. The pattern is now tolerant of trailing
  fields, still bounded to one object literal.
- **`withIdempotency` deletes its claim when the work throws**, which is what makes a corrected
  retry under the same key safe — the duplicate-warning override path depends on it.
