## 1. What changed

Two modules, `modules/membership` (instruments: plans, instances, covered members, entitlement
counters, coupons, recognition, the holder-book import) and `modules/partners` (counterparties,
versioned agreements, the append-only accrual ledger, receivable expectations, statements, the
channel P&L). The split is not cosmetic — see §3.

The counter can now **recognise** an instrument, **honour** its benefit through the Plan 06 pricing
contest, **consume and restore** entitlement counters, **redeem and release** coupons, **import** a
partner holder book into a reconcile queue that never auto-links, **accrue** commission from the
event stream, and **expect, match or dispute** a receivable against a partner statement. Sales are
not built; five flags hold the rest off.

the string `"false"` as TRUE. **Do not "simplify" them to booleans.**

## 3. Rules the code enforces — do not simplify these away

- **`modules/tariff/` is BYTE-UNTOUCHED, and the design is what makes that possible.**
  `AdjustmentSource.propose` is pure and sync, so membership and coupon ship as **factories** closing
  over a pre-resolved value, composed at the *billing* layer:
  `{...base, sources: [...base.sources, membershipSource(r), couponSource(r)]}`. **Teaching
  `loadPricingContext` about memberships is the obvious refactor and it is wrong** — it amends a
  frozen money module to buy nothing. Source order `[rule, manual, membership, coupon]` is a ruling:
  ties break toward the standing hospital rule, then the durable relationship, then the one-shot.
- **The accrual consumer REGISTERS ALWAYS and advances its cursor ALWAYS; the flag decides only
  whether it WRITES.** Registering conditionally is check-on-execute wearing a manifest's clothes,
  and it is silently lossy: no subscription means no cursor, so a later flip starts from *now* and
  every earlier event is gone. **Verified live**: `partners.accrual` sits at the same `event_cursors`
  sequence as `kernel.alerts` and `kernel.notify` while `commission_accruals` holds zero rows.
- **The accrual base is credit-aware and appended as a DELTA TO TARGET, not per-payment.** The first
  version scaled by `invoices.net_payable_paise`; a spike measured it producing 63 543 where 45 000
  was correct, because `invoices` and `invoice_lines` are immutable so a credit note moves neither.
  Four events drive one code path — `payment.received`, `payment.refunded`, **`allocation.reversed`**
  and **`credit_note.issued`**. The middle two matter: `reverseAllocation` and `markEnteredInError`
  both emit `allocation.reversed` and **neither emits a refund event**, so a consumer on the obvious
  two names accrues and never gives it back.
- **`external_rmp` is unpayable at the SCHEMA level** — a UNIQUE `(id, payee_class)` on
  `counterparties`, a composite FK from the ledger, and a CHECK. All four bypass probes were refused
  by Postgres. **The FK must keep its default `ON UPDATE NO ACTION`**: under `CASCADE` the FK stays
  satisfied and only a child CHECK refuses, so a later ledger table without that CHECK would be
  silently relabelled. A counterparty's class is frozen while any accrual row exists — so a status
  change is `counterparties.status`, never a class change.
- **Every catalog is DATA.** No plan code, partner code, coupon code or rate exists anywhere in
  `apps/`. `catalogs-empty.test.ts` enforces it without naming a single secret. The out-of-git
  context files at `/opt/hmis-context/` are never read by code and never quoted into a tracked file —
  fixtures invent their own people.
- **Entitlement counters: `SELECT … FOR UPDATE` on the parent, plus a partial unique index on
  single-use redemptions.** Both are load-bearing and both were measured: 0/20 over-consumption with
  the lock, 20/20 without; the index fired 10/10 with the lock removed. The lock turns a raw `23505`
  into a typed refusal; the index is what stops the second redemption landing.
- **Partner-facing output carries instrument ids, never patient identity.**

## 4. Landmines

1. **Four censuses move when you touch this module**, and three of them were discovered the hard
   way: the SPA route count in `caddyfile-parity.test.ts`, the **seed census** in
   `deploy-parity.test.ts`, the **consumer census** in `worker/seed-cursors.test.ts`, and the seven
   in `seed-roles.test.ts`. **The general rule: grep the test tree for `toHaveLength(` and
   fixed-array equality over anything your change adds to.** A "checked and clear" verdict about a
   *file* is worth nothing — the unit is the assertion.
2. **`truncateAll` carries sixteen of the seventeen new tables in the patients-group statement.**
   Postgres checks FK constraint *existence*, not row counts or statement order.
3. **Bare `loadConfig()` in a test is now an eslint ERROR.** `apps/core/.env` exists on this host and
   never in CI, so such a test passes here and fails there for ever. Pass an explicit env object.
4. **Every actor column in this phase is plain text, never an FK into `users`** — the
   `events.actor_id` precedent. That is what keeps `truncateAll`'s users statement unchanged.
5. **`membership_grace_honor` reaches production only because `seed:membership` is in `deploy.sh`.**
   A commit needing an operator step is a defect on a shared branch (protocol §5).

## 6. If you are the one who flips the flags

The order is not arbitrary. **Counter discounts cannot backfill** — a benefit not applied at billing
time needs a credit note, an approval and a queue — while accruals *can*, from event history.

1. Recognition is already deployed and inert. Confirm the catalogs you intend to honour are loaded.
2. Run the holder-book import; **clear the reconcile queue** (it never auto-links a holder to a
   patient — that is a human decision).
3. `MEMBER_BENEFITS_ENABLED` — this arms the counter.
4. `COMMISSION_ACCRUAL_ENABLED` / `RECEIVABLE_COMMISSION_ENABLED` **only after the CA/counsel
   register is signed** (O-8). Then run the **replay** job: the ledger fills in from event history,
   which is the whole reason the consumer has been tracking the stream while writing nothing.

**Assign `membership_admin`** at `/admin/users` — it exists with correct grants and zero holders,
alongside `mrd_officer`, `tariff_editor` and `biomedical_engineer` from the roles lane.
