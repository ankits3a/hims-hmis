# PLAN — ICU IC-1: core (#984)

Spec: `docs/specs/984-icu-core.md` (approved 2026-10-26). Rulings: decision 0090. Lane `icu-984`, built on
`lane/ipd-train` (#967). It merges after #966 and #967 and stays dark behind `HMIS_MODULES_ON`. New module `modules/icu`.
Paths are under `apps/core/src/` unless they start with `apps/`, `tools/`, `packages/` or `docs/`.

## What exists (read on the train)

- **No HL7, MQTT or Timescale.** The database is plain Postgres 16.
- **Closest models:**
  - lab ingest (`modules/lab/ingest.ts`, `lab-instruments.controller.ts`): a whole transmission, `transmissionRef`
    idempotency, the device clock stored but not trusted;
  - interface heartbeats (`kernel/ops/interfaces.ts`, `interface.down` / `interface.restored`);
  - the lab critical ladder (`modules/lab/critical-ladder.ts`);
  - the print relay edge program (`tools/print-relay`).
- **`device` resource kind** belongs to radiology (`modules/radiology/kinds.ts`). ICU reuses it with `in_use` and
  `occupant` set to the admission.
- **ICU approval gate:**
  - built: `ipd_icu_admission`, `requireIcuApproval`, `askApproval`, `askEmergencyIcuApproval`;
  - not seeded: the `intensivist` role;
  - missing: a "hold" outcome, the priority class, and an OT source.
- **`ipd_vitals`** has `source` and `device_id`, but `recordVitals` refuses device rows and has a 24-hour age limit.
- **eMAR infusion events** carry the ordered rate. There is no pump feed under option A.
- **Charges** have no device component. Device-day billing is a money ruling, so IC-1 only counts the days.

## Decided (standard practice; none is money)

| Question | DECIDED |
|---|---|
| Numerics sampling | The gateway sends one sample every **5 s**, batched each 30 s. Live tiles poll every 5 s. Waves and per-second detail stay on the maker's station (option A). This keeps WAL and backup growth small. |
| Retention | 5-second rows are kept 72 h in daily partitions, which are then dropped; under a legal hold they are copied first. One value per minute is kept with the medical record. The signed hourly chart is the legal record. |
| Alarms from the maker's station | Taken from HL7 when the vendor exports them, which is a purchase requirement in 0090. Until then HMIS raises advisory alarms only: a sustained breach of the doctor's limits for 20 s. Life-threatening classification comes only from the device. Both are displays and tasks; the monitor sounds the real alarm. |
| Regulatory scope | Forwarding device alarms as tasks and notifications sits under the same adviser check as option B (0090 §2). Advisory threshold alarms built from the stored numbers ship with IC-1. |
| EWS on ICU beds | The NEWS2 score is still shown. NEWS2 alerts are suppressed on ICU beds, because ICU alarms and bundles replace them. |
| Doctor-set limits | They drive the HMIS display and the ladder. Each order raises a task, "set the same limit on the monitor", which the nurse ticks. |
| Gateway authentication | The agent key is bound to `icu_gateways.agent_id`, with a Caddy IP allowlist for `/icu/feed/*`. mTLS is not needed for v1. |
| The "station" rung | The ICU in-charge on duty in that hall (roster position `ward_incharge` at the hall), else the nursing supervisor. |
| Ladder clocks | Bed nurse 60 s, then station 60 s, then duty doctor 120 s, then intensivist. A new job, `sweepIcuAlarms`, runs every 10 s (five job censuses to update). |
| Bed swap re-attribution | Numbers follow the device link at the moment observed. Numbers held "unconfirmed" between a swap and the re-scan are attached after the re-scan. Rows already in a signed hour are never rewritten. |

## Owner question still open (money)

device-days and line-days and does not post charges until this is ruled.

## Gateway contract (option A)
- **Edge program.** `tools/icu-gateway`, built like `tools/print-relay`. It receives MLLP HL7 v2 ORU^R01 and sends ACKs.
  It turns messages into JSON carrying the raw OBX codes and units, and keeps an on-disk spool for replays.
- **Batch call.** `POST /icu/feed/:gatewayId/batches` with `x-agent-key`. The body is
  `{batchRef, sentAt, samples[≤120], alarms[]}`. The reply is `{accepted, duplicate, quarantined, serverTime}`. An
  unmapped code is quarantined and raises a notice; nothing is dropped.
- **Clock.** skew = received − sent. If |skew| ≤ 120 s, observed = device time + skew. Otherwise the batch is flagged
  `icu.clock_drift_flagged` and uses the received time.
- **Heartbeat.** Every 30 s, with `staleAfterMs` set to 300000. That gives D7's 5-minute grey-out through the existing
  60-second sweep.

## Risks
- Numerics must never become events, or the event log floods. There is one event per gap, alarm or link.
- WAL and backup growth: watch the first week. 5 s sampling is the agreed default.
- Whether the vendors' central stations export alarms over HL7 is unknown until purchase. Advisory alarms cover the gap.
- Alarm storms: cap them per bed and flag to the in-charge.
- The signed vitals writer must bypass the 24-hour age check only for `icu_chart`.
