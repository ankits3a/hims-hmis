## 5. DECIDED and RULINGS

**DECIDED (Indian-corporate-hospital standard; one line each).**
1. Patients see **position**, staff see **minutes with an age**; the predictor is a read model, informational — L1 order is never touched (22c-D DD4; doc 20:26).
2. Pace = per-doctor median of the trailing 30 completed consults, computed on read, `n ≥ 10` else the department constant, which stays as the fallback; the quote is persisted (`wait.quoted`) so it can be scored.
3. The 20-minute rule reads the measured pace once E1-M1 lands; a doctor on leave or with an empty session never wins the comparison (the FD-7 T8 lesson).
4. Delay declaration is one tap by the doctor or PA on the session; it shifts class computation only; the desk tells the clerk today; patients are told by template **once WABA + DLT exist** (R-020; `NOTIFY_PROVIDER` is `console`-only until P4).
5. `slot_minutes_by_type` defaults to the 10-minute ruling for all types; values change only from 30 days of medians, rounded to 5, signed by the OPD head — "dynamic" = set from data, never re-ordered by a model.
6. A longer booking claims consecutive starts under the existing partial unique index; no second arbiter (22c-C DD1's rule kept).
7. `post_procedure` is a fourth visit type, not a fee class: fee follows the revisit rule; inside the day-care package window the package covers the review (Plan 15 DD6/F8 — the package's price is O6's, its coverage rule is the package definition's); anchor = `daycare.discharged` with a review date once the OT opens, `admissionAdvised` until then.
8. Overbooking is config per R-216/R-217: 15 % default, 25 % only when trailing no-show ≥ 12 %; unconfirmed slots released only on overbooked sessions and only once a confirmation channel exists (P4).
9. 16b is approved as authored and re-based, not re-designed; **the snapshot card's home is 16b, not 12b** (`12-agentic-copilot-layer.md:623`; 12b adopts; 12b's "12a live 30 days" gate does not apply — `copilot-design.md:172`: zero inference, zero DPIA gate; 16e owns the later dispense-history section, doc 16:569); **the card assembles the past and the CDS library answers the present** (`GET /opd/cds/*`, on `main` since 09-15) — one screen, two disjoint data sets, no duplicated reader; NKDA is a positive `no_known_allergies` row with a recorder, its wording signed by the MS (clinical policy — register legend `:281`), asked at 16b's kickoff as Q5 requires (`16b:21,58`).
10. "Suggests clinical considerations" = deterministic check hits + cited restatements + protocol prompts; free-form differentials are not built (T2 cap; SaMD to counsel).
11. Rx pre-fill is **the CDS regimen that exists** (syndrome-keyed, from the owner's bundle, `PLAN-CDS-copilot.md` §4 T3/T4), curated beyond the bundle under an MS-held permission until a `department_head` is seeded, applied only by the doctor's tap as editable lines, checked by the same engine at issue; `rx.regimen_applied` is its provenance — a regimen is neither an automation nor an agent (spec `:780`) and carries no tier word; **no second `rx_templates` table** (the name is occupied).
