## 0. The mission sentences this pillar serves, and the honest reconciliation

**Mission (verbatim):** "patient monitoring capabilities that adjust alerts based on individual clinical histories rather than fixed thresholds" · "automated drug–drug interaction checks" (beta) · "AI-based post-surgical wound assessment through remote image scans" (beta) · "track pre-/post-surgery range of motion for joint replacements; alert clinical teams if recovery strays from the expected trajectory" (beta).

**What is true today.**
1. *Monitoring.* One surface in production: the OPD vitals bay (VD-2 `451458b` ⊂ `399f92c`; `/opd/vitals`, `apps/web/src/router.tsx:661`). Thresholds are four age bands held as `opd_config` DATA since the owner's 2026-08-15 decision (`apps/core/src/modules/opd/config.ts:116-143`); `evaluateVitals(v, band, cfg)` takes no patient argument (`vitals-rules.ts:175-213`), `bandFor` reads age only (`:122-126`). Adult pulse < 50 is `danger` (`config.ts:137`); a double-confirmed danger reading sets queue class 0 by itself with a 10-s cancel (`escalation.ts:21-33`). **The mission's runner is a live false positive.** No per-patient baseline exists in code, plans, the §16 roster (SPEC:782-787) or the register; nearest: the ICU limit order, intensivist-signed, 24-h expiry (ICU:99,163; R-070 REG:82).
2. *DDI.* Plan 16a is merged, closed and deployed: pairwise checks at issue time inside the transaction (`modules/opd/rx-checks.ts:169-184`; `prescriptions.ts:255-261`, refusal `:373-382`); the dispense re-check refuses an un-overridden severe pair (`modules/pharmacy/verify.ts:185-205`). Zero pairs → `[]` (`rx-checks.ts:186`). The 26-pair floor is seeded by `deploy.sh:467` on every deploy (`399f92c:675` too), so production *should* hold 26 pairs — **no census row reads it** (`grep formulary scripts/standup-check.ts` → empty) and a session may not query prod: inferred, not measured. The override rate has a numerator (`opd/events.ts:341`) and no denominator (16a plan `:377-381`, F22). Curation is half-built: `PATCH /formulary/interactions/:id` (`formulary.controller.ts:267`) → `updateInteraction` (`masters.ts:316-335`) → `interaction.updated {interactionId, changed}` (`formulary/events.ts:60-62`) with no `reason`, no screen (`formulary-admin.tsx` has no interaction UI), and `formulary.manage` held by "a role with no humans in it" (`formulary/manifest.ts:32`). The mission's "real-time before adverse events" is met by COP law 2 (`:27`); the gap is evidence and data, not code.
3. *Wound images.* No patient can upload anything: no `patient_credentials`, no multipart endpoint (grep of `apps/core/src`: two comments only), 22c-A…F "NOT APPROVED FOR EXECUTION" (22cA `:3`); the only image write is staff-side at 512 KB (`schema/patients.ts:200,264`). The nursing brainstorm **rejected** a wound-photo assessor — "clinical image inference, no DPIA basis — not before stage 4" (NUR:464) — text-only day one (NUR:587). The DPIA never mentions images; Class 2 never enters an inference request (DPIA:20); the speech carve-out (DPIA:31-33) is the only template for such a modality. R-169 needs a written photography/consent policy before any image-capture feature ships (REG:181). The deterministic surveillance the series designed — `ssi_register` (OTD:156,550), day-30 wound micro-survey Q-4 (QUA:350; O-15 QUA:526), `ssi.followup_recorded` (QUA:92) — is **not built**: `schema/ot.ts` holds only `wound_class` (`:276`), and `dischargeDaycare` enqueues no follow-up task despite DD10's promise (`recovery.ts:443-506`; P15 `:155,:190,:339`; `:549` comment vs `:575-579`).
4. *ROM.* Plan 25 is Track C, not IPD-gated, dependencies shipped (`00-INDEX-AND-SYNTHESIS.md:71`), no phase doc. Designed: `outcome_scores` with `ROM` + `body_site` (PHY:156), goniometer widget (PHY:417), packs with milestones (PHY:416), surgeon-clearance gating (PHY:330), the ortho path opened by `daycare.discharged` "with procedure code" (PHY:90). The event carries no procedure code (`modules/ot/events.ts:84-86`); no pre-op step exists; "trajectory"/"arthroplasty" appear in none of the 22 docs. Session departments go live with exactly four active alerts (PHY:63).

**Reconciliation.**
- *Tiers.* Clinical actions cap at T2–T3 permanently (SPEC:778); "where a rule is safer … the rule wins" (SPEC:780). Every capability below is a deterministic automation (T0/T1) or a human order; nothing calls a model. - *"Individual histories rather than fixed thresholds"* → **a doctor's dated per-patient limit order, consulted by the BOARD decision only, never the chart** (VD-1 D4, `plans/2026-08-31-phase1-vd1-vitals-rails.md:52`; `vitals.ts:262-266`), plus a deterministic proposal from the patient's own unflagged prior readings (`history.ts:125-146`). - *DDI beta* → **evidence**: a census row proving the pairs exist on production, a denominator event, a DTC curation seat. The licensed dataset (₹8–12 L/yr, RM:37,450) stays 16e's and procurement's.
- *"Vision AI wound assessment"* exceeds what is lawful or designed on four counts (no patient actor, no upload rail, no DPIA image basis, no photography policy), upstream of a brainstorm that said no. **Reconciled goal: every day-care surgical patient has a wound outcome recorded by day 30, text-first**, through the chain already designed (recall task → day-30 survey → ICN call task → `ssi_register`); a consented photo may attach to a NURSE's structured escalation as a human-read artefact (home-care H-8, `03-home-collection-home-care.md:380`; N-P5 NUR:319) only after R-169's policy exists. - *IPD gate.* Nothing here needs 41/42a/49/50 (RM §5:419); the baseline order is the OPD-scale precedent those plans inherit (one table shape; the chart flag is never weakened).
- *Absorption first* (RM Q2). The vitals bay is deployed with no runbook and no census rows of its own (`docs/runbooks` = four files; `standup-check.ts:183` = one `opd_config_present` row); the mini-OT is deployed, not opened (RM:418). ## 5. DECIDED and RULINGS

**DECIDED** (Indian-corporate-hospital standard; one line each):
1. A baseline is a doctor's dated ORDER, never a learned suppression — R-070's ICU limit order (ICU:99) at an OPD horizon; COP law 3 `:28` intact; the chart flag never weakened (VD-1 D4 `vd1:52`).
2. Orders widen only toward the patient's own history; SpO₂ and SBP floors stay absolute in OPD — every corporate OPD's safety floor.
3. Order life: next consult or 12 months, whichever first; R-070's 24 h is an ICU horizon.
4. Proposal arithmetic: median ± k·MAD over ≥ 4 unflagged readings; constants as `opd_config` data (`config.ts:116` precedent); the DTC revises later.
5. Proposals and lapses are T1 nudges to the cockpit, batched; the bay is never nudged (index `:198`).
6. "Far from usual" is a chart-only `notice`, record-only for its first pilot week (NUR:583); `dangerOf` keeps filtering notices (`escalation.ts:148`).
7. Sealed patients: the order is not answered at the bench (VD-2 M3 `:215`); the cockpit reads it under PHI logging.
8. A medication change after the order re-opens it by nudge; only a person cancels ("ASKS — anything that downgrades urgency").
9. Fail direction: unreadable table or absent config → band behaviour; the system fails toward the alarm.
10. DDI beta = evidence, not more code: two census rows, one denominator event, a screen and a `reason` on the curation path that already exists (`masters.ts:316`); the seed is never authority (COP D2; seed `:14-19`).
11. The refusal event is appended on its own transaction (17d's audit rule) so a rolled-back prescription still leaves its refusal on the log.
12. Coverage 80 % (COP:61) is a harvest target, never a gate on prescribing (COP law 1).
13. No Vision-AI wound assessor this year: rejected (NUR:464), four prerequisites unowned; the beta is text-first SSI surveillance (NUR:587) plus a nurse-attached, human-read photo (H-8).
14. The day-30 survey is a call task first and a WhatsApp message only with a real adapter and a registered template; templates only, forever, to patients (R-020; QUA:526).
15. A positive survey answer opens an ICN task with a 24-h active SLA — the mini-OT's third active alert, in the definition.
16. The wound photo is staff-side, in-app, no gallery persistence (NUR:319), `bytea` under 22c-D's 2 MB cap, sealed-aware (NUR:177), default-off; a lint rule keeps the bytes away from `kernel/inference`.
17. Pre-op ROM lives on the OT case at PAC (the surgeon's record) and rides the discharge event; 25 copies it as score #0 — 25 need not exist to capture it.
18. Trajectory band = pack's day-N expected ROM ± tolerance; flag on two consecutive below-band scores or no score by a milestone day; missed sessions are recalls (SPEC:281 map 11).
19. The Watcher is the session definition's fifth active alert (PHY:63) with ladder therapist → rehab head → surgeon; `off_trajectory` is batched.
20. Packs' numbers ship as published normal ranges, Class-B drafts revised by the surgeon at UAT — the DEFAULT_DANGER_RANGES pattern.
21. Inter-rater spread on one joint in one day is a `notice`; the watcher uses the signed score.
