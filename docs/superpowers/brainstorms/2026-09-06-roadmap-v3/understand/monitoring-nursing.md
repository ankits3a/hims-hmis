# monitoring-nursing — pillar 4a (personalised monitoring) and 4c (Vision AI wound assessment)

Read-only survey of `origin/main` @ `b04cbd9` (2026-09-06). Paths are relative to the main-ro checkout. Deployed base is `c11833d` (56 migrations, never left `commissioning`). Status vocabulary: deployed / merged / authored / brainstormed / absent / open / blocked.

**One-paragraph answer.** The hospital has exactly ONE monitoring surface today: the OPD vitals bay (Bay One), deployed, with **fixed age-banded thresholds stored as `opd_config` data** and a rule that reads no patient history at all. Nothing anywhere — code, plan, or brainstorm — defines a per-patient baseline; the closest designed thing is the ICU brainstorm's *per-patient alarm-limit order* (intensivist-signed, 24-h expiry). Continuous monitoring, EWS scoring and any deterioration watch are entirely behind the IPD gate (41 → 42a → 49/50) and this quarter builds nothing behind that gate. A patient cannot upload any image today: there is no patient identity, no portal, no multipart endpoint on the server; the only image path is a staff-taken 512 KB registration photo. The nursing brainstorm **explicitly rejected** a wound-photo assessor ("clinical image inference, no DPIA basis — not before stage 4"), the DPIA v0.1 does not mention images at all, and its Class-2 law ("identified health data never enters an inference request") plus the speech carve-out are the only template for how a wound image could ever reach a model.

## 1. vitals-thresholds-today — DEPLOYED, fixed, age-banded, data not code

**What exists.**
- Rule: `apps/core/src/modules/opd/vitals-rules.ts:122-126` `bandFor(ageYears, cfg)` picks a band by AGE ONLY (unknown DOB → adult tail). `vitals-rules.ts:175-213` `evaluateVitals()` compares every present ranged vital (`sbp dbp pulse rr spo2 tempC`, `:106`) against `band.ranges` (→ `severity: "danger"`) then `band.noticeRanges` (→ `severity: "notice"`), plus MUAC zones. **No argument is the patient, the diagnosis, the medication list or the prior readings.**

Paediatric fever notice `tempC.max 37.9` under 13 (`:125,128,134`). Gates `adultWeightFloorKg 25 / heightDeltaCm 3 / spo2ProbeFloorPct 75` (`:141`), MUAC SAM < 11.5 / MAM < 12.5 (`:142`).
- They are DATA: `config.ts:116` *"owner decision 2026-08-15: clinical staff revise at UAT — data, not code"*; loaded from `opd_config` row `main` (`config.ts:178-192`), patched via `config.ts:244-249`, exposed under `opd.masters.read` (`opd-masters.controller.ts:213-221`). The bay receives the band's limits inside the pre-stage (`prestage.ts:60-63,161-162`) because `vitals_desk` does not hold `opd.masters.read` (VD-2 C1, `docs/superpowers/plans/2026-09-02-phase2-vd2-bay-one.md:210`).
- Storage: `apps/core/src/kernel/db/schema/opd.ts:442-548` `opd_vitals` — scalars + `band` + `dangerFlags` jsonb + `readings` jsonb (takes / source / held) — migration `apps/core/drizzle/0049_vitals_bay.sql`.
- What a danger flag does: sets `opd_encounters.danger_flagged` and fires `vitals.danger_flagged` (clinical record, never unset — `escalation.ts:45`); the BOARD moves only through the protocol *danger → recheck demanded → second confirm → class 0 → 10-s cancel* (VD-1 plan `2026-08-31-phase1-vd1-vitals-rails.md:108-112`; VD-2 `:115-117`). The only consumer of `vitals.danger_flagged` today is the OPD realtime fan-out (`apps/core/src/modules/opd/realtime.ts:11`); no router, no ladder.
- Deployed: VD-2 T5 `451458b` is an ancestor of `c11833d` (checked with `git merge-base --is-ancestor`); `c11833d`'s `config.ts` already carries `noticeRanges` (5 hits); Bay One IS `/opd/vitals` by the owner's ruling 2026-09-02 (`apps/web/src/router.tsx:153-156, 661-670`). 11i T9 redirects `/opd/vitals/bay → /opd/vitals` for one release (`2026-09-06-phase1-11i-the-stand-up-path.md:373-378`).

**Gap for pillar 4a.** A 42-year-old marathoner with resting pulse 44 is a `danger` flag under `adult.pulse.min 50`, gets the other-arm recheck demanded, and a second 44 bumps them to class 0 — exactly the false alarm the mission names. The only knobs are hospital-wide (`opd_config`) and per-band; there is no per-patient dimension in the schema, the rule signature or the config.

**Measurable parameter.** `dangerFlags` per 100 charts by band and by vital, and the ratio *recheck_demanded → escalated* (both are `opd_vitals.dangerFlags` and `opd_queue_entries.escalation` reads today). A baseline mechanism is proven when the pulse-min flag rate on patients with a stored baseline falls while `vitals.danger_flagged` on patients WITHOUT one is byte-identical.
