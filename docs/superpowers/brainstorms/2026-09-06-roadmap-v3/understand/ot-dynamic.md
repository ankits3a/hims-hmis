## The one-paragraph position

The mission asks the OS to "analyse surgeon availability, OT capacity, procedure type, anaesthesia and equipment needs to auto-schedule and continuously rebalance surgical timelines in real time if delays occur." What exists is Plan 15's mini-OT spine, DEPLOYED (the `ot` module is in the deployed base `c11833d`: 42 files under `apps/core/src/modules/ot/`, migration `0035_mute_vision.sql` ≤ the 56 deployed) but deploy-dark: one theatre resolved by code, a versioned list with a human publish, a whole-list re-sequence with no event, five server-stamped timestamps, and a 60-second surgeon-late job that reads a typed planned-start off the NPO gate. There is NO planned start or planned duration column, NO overrun projection, NO rebalance proposal, NO roster, NO equipment gate, NO turnover dispatch, and the list's publish event has zero subscribers. Everything the mission names beyond that is brainstormed in doc 15 §9 (Overrun Cascade T1→T3, OT List Optimiser T2, Turnover Dispatcher T4) and routed to 15d / Plan 48 (major suite, behind the IPD gate) / Plan 20 (roster) / 29 (BME) / 31 (transport). The roadmap v2 calendar does not open the mini-OT this quarter at all (§2 has no OT row; §5: "not 29/31 — no consumer until 15 opens for real").

## ot-list-scheduling — EXISTS (deployed, dark); no times, no durations, no fan-out

## Surprises

1. **`resequence` is silent** — the one dynamic act the module has writes no event and no version (`lists.ts:173-209`), while doc 15 §3.3, spec §11.16 and doc 19 T3 all depend on `ot_list.resequenced` to re-time NPO, wards and porters. The printed v1 in a nurse's hand can disagree with the screen with nothing in the log.
2. **The mini-OT is deployed and not on the roadmap calendar.** Roadmap v2 §2 opens lab, pharmacy, radiology and the front desk; the OT — deployed since the base image — has no opening week, and §5 defers 29/31 "until 15 opens for real" without saying when that is.
3. **Turnover is a status nobody clears.** `onRelease: turnover` was built as the safety property ("a theatre that returned straight to `available` would let the list screen offer a slot in a room still holding the last case's instruments", `kinds.ts:27-32`), but the registry's assign rule admits `onRelease`, so the next sign-in walks in anyway.
