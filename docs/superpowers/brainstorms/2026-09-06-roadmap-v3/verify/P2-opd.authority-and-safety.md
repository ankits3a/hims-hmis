## 1. KILL — one milestone as written

### K1 · E4-M3 "The scribe for one cohort" runs clinical dictation on the DESK carve-out, and the transcript is already persisted where no retention rule, legal hold or PHI log can reach it

**The design's claim** (P2-opd.md §3 E4-M3): depends on M1 (the §3-A accept + counsel signature), M2 (voice search on) and E3-M3; acceptance "no transcript column anywhere (schema grep); audio never persisted (test) · on-prem/in-region ASR (12 §9.6) swaps behind the same `SpeechClient`"; size "3 d; owner's money **if** on-prem ASR". The RULINGS row "On-prem ASR box … **defer until E4-M1 says it is required**". DECIDED 14 and edge 10 repeat "nothing is stored".

**Refutation, three parts.**

(a) **The transcript IS persisted today, at the route the scribe uses.** `apps/core/src/kernel/inference/speech.controller.ts:108` calls `attachTranscript(this.db, auditId, text)`; `apps/core/src/kernel/search/audit.ts:167-170` writes the transcript into `search_audit.raw_query` (`.set({ rawQuery: text, queryHash: hashQuery(text) })`). The schema says of that column: "The query AS TYPED. It is personal data" (`apps/core/src/kernel/db/schema/search.ts:37-41`). Retention is a 90-day sweep (`audit.ts:12`, `:121-133`) that by design honours **no legal hold**, because the row "references no patient" (`audit.ts:114-119`). `consult-scribe.tsx:91` posts to exactly this route (`POST /speech/transcribe`). So a doctor's 15-second clinical dictation — diagnosis, drug names, very often the patient's name — would land as `raw_query` in a table built for desk search strings, keyed to the doctor's actor id, with no encounter link, no `phi_access_log` surface, outside the medical record and outside R-009's schedule. The scribe component's own comment "NO TRANSCRIPT IS SENT ANYWHERE. No route stores one" (`consult-scribe.tsx:41-43`) is false about the server it calls. The design's acceptance test "schema grep for transcript columns = 0" would pass today and prove nothing — the column is named `raw_query`. That is the `test-can-pin-the-wrong-layer` shape.

(b) **Cloud ASR for a clinical narrative is refused by every artefact the design cites, and the milestone's dependency set permits it.** DPIA §3-A scopes the single named exception to "Voice search (Plan 11h DD11) transcribes **desk utterances**" whose "transcript enters a **deterministic parser** as data" (DPIA:33). The scribe's transcript enters a clinical note by `Insert` (`consult-scribe.tsx:37-40`) — not a parser. Brainstorm 12 §9.6: "**clinical dictation for drafters is a separate, later carve-out** requiring in-region or on-prem ASR … cloud ASR for clinical narratives is not proposed" (`12-agentic-copilot-layer.md:514`); §9.11: "on-prem whisper.cpp **before any** clinical dictation" (`:541`). R-059's default: "ASR only per 11h DD11" — DD11 is the desk (`00-OWNER-RULINGS-REGISTER.md:71`). The design's own RULINGS row for R-059 says the same ("on-prem/in-region ASR for clinical narratives"). Yet E4-M3 depends only on M1+M2, prices the on-prem box as conditional, and the RULINGS row defers it "until E4-M1 says it is required". As written, a lane can switch the scribe cohort on over Cloudflare Workers AI (not region-pinnable to India, DPIA:33) the day the desk carve-out is accepted. That is Class-2 health data, cross-border, on production, under an exception written for another flow.

(c) **R-009 pulls the other way and the design does not say so.** The register's retention default reads "dictation audio 90 d post-sign" (`00-OWNER-RULINGS-REGISTER.md:21`, legal, counsel confirms). The design's "audio never persisted (test)" is the opposite. Both are defensible; the design must state which applies to push-to-talk ASR clips and put the question on the same counsel agenda (L1 in `rulings-gates.md:147`).

**Amendment (rewrite E4-M3).** Gate = its **own** DPIA carve-out or the spec §19 amendment naming *clinical dictation* (not the desk's §3-A) **and** in-region/on-prem ASR present (move the "On-prem ASR box" RULINGS row from "defer" to "required before M3", or name an Indian-region ASR provider under DPA — `rulings-gates.md:145` P4 already lists "an Indic ASR provider with DPA"). Build = a **separate route** (`/speech/dictate` or a `purpose:'dictation'` field) whose audit row never writes the transcript text — `recordVoiceEgress` without `attachTranscript` — or, if the transcript is to be kept, it is kept as a **medical-record artefact** on the encounter under R-009, never in `search_audit`. Acceptance = "the `search_audit` row for a dictation carries an empty `raw_query` (test)" and "`SpeechClient` provider for `purpose:'dictation'` is in-region (config assertion)". Add one RULINGS line under R-059/R-009: "push-to-talk clips: persist (R-009 90 d) or discard (DPIA §3-A) — counsel, same session".

## 2. AMEND

Its blockers file records a lane correctly **declining a relayed approval** (`BLOCKERS.md:1221-1225,1631`). The design invents an approver. Fix: E3-M1's human act = "the owner's one approval line (after the re-base is in the header)"; §7(b) likewise. Nothing about the *content* of 16b is money/law, so the design may DECIDE every open question inside it — but approval of the document is the owner's act by the method the orchestrator runs under.

### A3 · Patient messages in E1-M2 / E6 need a procurement the RULINGS table omits: WhatsApp WABA + DLT

E1-M2 tells patients about a declared delay "by template (R-020)"; E6-M3 sends a UPI link. ## 3. NOTES

- **N1 · GST-on-MRP is filed as a ruling; the design's own default calls it statute.** Legal Metrology (Packaged Commodities) Rules 2011 make the printed MRP tax-inclusive; the choice is not open. The pharmacy lane already sent it to the owner (`rulings-gates.md:20`) so P2 inherits the wait, but the standing rule would let a phase DECIDE "inclusive; back the slab out of MRP" and leave only the **slab rates** to the CA at O6. Holding E6 entirely on an inclusive-vs-exclusive line costs a quarter for a question the statute answers.
- **N2 · DECIDED 11 "T2-equivalent (template)" is a category error.** Spec §16 defines *automations* (deterministic, under the harness: identity, kill switch, heartbeat, tier) and *agents* (inference) (`spec:780`). A department Rx template is neither; the label imports the harness's provenance and kill-switch expectations without building them. Say instead: "a template is applied only by the doctor's explicit act, never auto-fired on diagnosis entry; `rx.template_applied` is its provenance; the check engine at issue is its guard" — and drop the tier word. Same for E1's "T0 predictor as a pure read": a read model is not a harness automation; either give it the harness or do not call it T0.
- **N3 · DECIDED 9 (NKDA) silently resolves 16b's Q5.** 16b says the NKDA question "is asked at this phase's kickoff, **not silently resolved**" (`16b:21,58`). Under the 2026-08-28 standing rule it may be DECIDED, but it is clinical policy (register legend: `clinical` rows are "a corporate-standard default the **medical board** signs", `00-OWNER-RULINGS-REGISTER.md:281`). Name the DTC/medical board as the signer of the NKDA wording, not the lane.
- **N4 · DECIDED 7 (post_procedure fee) yields a charge the design does not name.** The revisit window is `follow_up_default_days = 7` (`kernel/db/schema/opd.ts:24`, "owner: 7"); `classifyVisit` returns `renewal` past it (`modules/opd/visit-type.ts:12`). A post-op review anchored on `daycare.discharged` at day 10 is charged as a new consult unless the surgeon extended (15/21/30, `opd.ts:25`) or the package says otherwise. Corporate default: post-op reviews inside the package window (30 d) are free. Either cite the `daycare_package` rule that covers it (Plan 15 DD6/F8, `…15-mini-ot-daycare.md:391`) or record it as the money line it is.
- **N5 · E5-M2's floor page carries no identity rule.** The role-broadcast alert reaches every `lab.collection.operate` holder; the design says the page names the floor, not the room (edge 12), but not that it carries the **token, never the name** (spec `:287`). One line.
- **N6 · E6-M3 names Razorpay as a processor of patient identifiers; nothing names it in a DPDP notice.** R-261 is DECIDED at PSS P-1 (`…patient-self-service/06-RULINGS-LOCKED.md:69`) and 22a1 is "NOT APPROVED FOR EXECUTION" (`…22a1-payment-money-in.md:3`); 22a1 carries no DPDP/processor line by grep. Add "Razorpay named as processor in the DPDP notice (R-128's notice)" to E6-M3 — a line, not a ruling.
- **N7 · `VOICE_SEARCH_ENABLED` is a source constant, not env** (`apps/web/src/lib/voice-flag.ts:27`). E4-M2 writes it as a config act. The server half's kill switch is real (unset `SPEECH_PROVIDER` → 503 → typing, `speech.controller.ts:65-66,89-90`); the web half needs a commit and a deploy. Say so.
- **N8 · DPIA sign-off table is at `:66-72`, not `:66-70`**; the file's header already reads "0.2 DRAFT … not reviewed, not signed" (DPIA:3), so E4-M1's "paragraph" is an amendment to an existing 0.2 draft, not a new version.
